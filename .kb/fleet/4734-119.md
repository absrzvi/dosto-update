# The B&E WAP-swap investigation (2026-05-21 → 2026-06-24)

- **Customer symptom (Anton, IBS):** on cars **B and E** the WE1/WE2 SSID ends feel *vertauscht*
  (swapped) vs schema — can't associate on the expected channel at a car-end. Reported across
  Fzg 19 / 20 / 21.
- **Ruled out (2026-05-21):** AP→switch-port mapping is uniform and consistent across all coaches
  (A/G run `APx-v1`, E/B run `APxm-v1`); pattern matches Fzg 20 exactly. **No swap at the OBN /
  cabling / switch-config layer.**
- **Root cause found (2026-06-24, proven live on 4734-121 / box1-t50):** the nv4 `rules.yaml` groups
  the AP config variants as `coach_number: [1,2]` (non-m) / `[3,4]` (m) — a **front-half / back-half**
  split. On an A→G→E→B consist that deploys as **A,G = non-m ; E,B = m**, putting the *same* plan on
  adjacent coaches A&G and E&B. The per-coach 5 GHz **mirror** (added by commit `868f189`) only
  staggers if the variant **alternates every coach** (ends non-m, middle m). rules.yaml disagrees
  with `nv4-topology.md` and is wrong. This is a **fleet-wide template bug, not per-train**.
- **Supersedes** the earlier 2026-06-03 theory that `AP*m-v1 wirelessFreq` was mis-assigned — that
  was wrong; rules.yaml is internally self-consistent, the defect is the coach grouping.
