# Coupling test — 4736-117 (master) + 4736-105 (backup)

Multitraction test on **2026-06-30**. Follow-on to the 2026-06-12 4736-110 + 4736-119 test.

- **Master / driver cab:** 4736-117 = **Fzg 145**, CCU `box1-t32` / `10.179.32.1`.
- **Backup:** 4736-105 = **Fzg 133**, CCU `box1-t1` / `10.179.1.1`.
- Both Fzg are **odd** → Stadler FW at `.129` on each train's vlan7.

# What the test proves (three parts)

1. **v9 RSTP** — set coupler `e0-2` port-cost **20000** on A1/A3/B1/B3 on both trains; prove the
   TC-churn (topology-change storm) freezes. This is the permanent fix for the asymmetric-cost
   TC storm seen on the 06-12 test (the 4736-110 template value `137999999` overflows 2^27 and
   re-arms the storm on every coupling until the nv6 template lands the <2^27 cost + max-age 38).
2. **Single-FW VLAN-5 routing** — repoint the BACKUP cameras' gateway to the MASTER FW via
   `configure ip dhcp-server group video default-router 172.18.200.129`.
3. **Prove A8** — Stadler downs the BACKUP FW VLAN-5 **SVI** (this is an SVI-down test, **NOT** a
   VLAN-5 coupler prune — the June prune hypothesis was refuted; VLAN 5 stays on the Frontkupplung).

# Key decisions (do not re-litigate)

- Measurement is **switch-PORT-TRAFFIC, not ping** — the CCU has no VLAN-5 leg.
- Staged S0 → S1 → S2; mutations are **echo-only**; **no `save running-config force`** (runtime only).
- This is a **one-day experiment, not a skill.**
- **Two live deps:** master FW needs a `/17` (or route) back to `172.18.194.0/24`; the counter-field
  regex must be validated with `harvest_ports.sh` first.

# VLAN-5 addressing

- Space `172.18.128.0/17`. Master cams `172.18.200.158+`, master FW `.200.129`.
  Backup cams `172.18.194.158+`, backup FW `.194.129`.

# Known quirks

- **Dark fabric on power-cycle.** Both trains power-cycled repeatedly during prep; after reboots
  0/18 sw + 0 AP were reachable on vlan100 (dhcpd serving, near-zero RX). The health check and the
  coupling test are **BLOCKED on the switch fabric returning** — needs consist power/boot
  confirmation on the ground. (Same quirk documented on [4736-105](4736-105.md).)
- **vlan7 was misrendered on both trains** and had to be fixed before the test: 4736-117 live +
  nmconnection were `172.19.208.2/17` (decodes Fzg 160); corrected to `172.19.200.130/17` via NDSU
  chroot (heredoc-into-stdin) + `safe_reboot`.
