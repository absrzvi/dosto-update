# The A1 cable saga (cable reg #10)

- **Root cause (re-diagnosed 2026-06-08):** not a misimage and not an absent switch — a **physical
  cable swap at the A1↔A3 coupler**. A1's vlan100 trunks (e0-0/e0-1) were plugged into the coupled
  Fzg-15 consist, while A1's coupler port (e0-2, VLAN 5/15 only) faced this train's A3. → A1 was
  unreachable on vlan100; all remote push transports (TFTP/HTTP/SCP) failed.
- **In-band pre-stage (2026-06-08):** A1 reached via a native-VLAN-1 workaround (`192.168.1.2/24` on
  CCU bond0 untagged → SSH+SNMP to A1 at `192.168.1.100`); config hand-corrected to train_id-9 and
  persisted, so a post-recable A1 would need no push. This did **not** restore service (still
  mis-cabled) — the fix required Stadler on-train re-cabling.
- **Resolution (2026-06-17):** Stadler replaced the A1 chassis (`d0:c1:c0`, `.186`), came up factory,
  re-cabled correctly (e0-0→A3, e0-1→G1, e0-2→Fzg15 coupler — LLDP-verified). `obn update c .186`
  pushed `nv4-A1-v8-009`. Old A1 (`d0:8f:a0`) now an isolated spare on A3 e0-2.

# Known quirks / dead ends

- **OBN Bug 6 was ABSENT on this 2.2.23 CCU** — contradicting the "2.2.23 ships bugs 1-10 native"
  assumption. `obn update c` crashed `AttributeError: 'NoneType' object has no attribute 'type'` at
  `tree.py:34` because the Fzg-15 coupler neighbour isn't in OBN's device list. Applied the canonical
  `if neighbour_device is None: continue` guard at **runtime** (wiped on reboot — persist via NDSU
  chroot if `obn` ops are needed again).
- **Coupler-neighbour false-positive:** an LLDP `nv4-A1-v8-015` seen on A3 was initially mis-read as
  a misimaged A1. It was the **coupled Fzg-15 consist** arriving on the Frontkupplung port. Before
  declaring a misimage, confirm the neighbour is on an intra-consist trunk (e0-0/e0-1), **not** a
  coupler port (desc "Frontkupplung"/"Heckkupplung", VLAN 15 transit).
- **`verify_reboot_started` 75s ICMP window can false-negative** — a fast reboot may not visibly drop
  ICMP. Trust the post-state (new hostname / low uptime / new lease), not just the ICMP-drop window.
